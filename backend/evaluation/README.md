# Evaluation JSON Files

## 1. eval_questions.json
```js
  {
    "question": "What does alarm AL088_CAP_CHECK_DEVICE_ALARM mean and how do I resolve it?",
    "expected_agent": "diagnosis"
  }
```
- Question + which agent should handle it. Generated by a script that pulls real orders, quotes, and alarm codes from the database and templates a natural question for each row. The expected agent is assigned by a fixed rule written directly in the script (order/quote → commercial, alarm code → operational/diagnosis, etc.) — no LLM is involved in deciding the correct label.
- 80 questions total.
- Purpose: test routing accuracy.

## 2. multi_agent_questions.json
```js
  {
    "question": "Is there an open order for this machine, and why does it keep raising the same alarm?",
    "expected_agents": ["commercial", "diagnosis"]
  },
```
- Question + which combination of agents it genuinely needs. Written by hand, grounded in real data: for each question, we first queried the database for real machines together with a real alarm, ticket, order, and quote actually attached to them, then wrote the question around that real combination (e.g. referencing a real alarm ID and a real ticket ID that exist on the same machine). The expected agents were then reasoned through by hand, using the planner's own category definitions.
- 15 questions total.
- Purpose: test whether the planner correctly combines multiple specialists on genuinely cross-domain questions.

## 3. rag_questions.json
```js
 {
    "question": "What are the four specific intervals of working hours defined for maintenance schedules between section 11.5.1.4 and 11.5.1.8?",
    "chunk_id": 2777,
    "machine_serial": "17478",
    "source_file": "17478_manual_EN.pdf",
    "page": 8
  },
```
- Question + which manual chunk it was generated from. An LLM was given a real chunk of a real manual and asked only to write a question that passage answers — the LLM never decides what counts as correct; the "correct answer" is simply the chunk it was given, which is known for certain by construction.
- 40 questions total.
- Purpose: test retrieval quality (does search return the correct chunk, and how highly ranked).

## 4. answer_questions.json
```js
 {
    "question": "What is the status of order ORD-2026-0006?",
    "machine_serial": "15610",
    "reference_fact": "Order ORD-2026-0006 has status 'Delivered' and shipment status 'Delivered'."
  },
```
- Question + a reference fact built directly from real database fields (no LLM involved). Scoped to one company, and for alarms, restricted to the ones actually inside the operational agent's visible context window (its 10 most recent), so the benchmark only tests what the agent can legitimately see.
- 13 questions total.
- Purpose: test final answer quality — does the system's real, generated answer match the real fact, scored by an LLM-as-judge (1–5).
